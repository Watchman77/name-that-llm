## Why this candidate

S07 already combines adapted causal Qwen and Llama, a DeBERTa stack, frozen-model representations, a sparse classifier, likelihood scores and prompt assignment. The public 0.684 family adds a separate trained Qwen3-Embedding-8B view, with multiple pooling depths and five calibrated adapter folds. The published [Heliosli V14 source snapshot](https://github.com/SSanjay0614/Name-That-LLM-Kaggle/blob/55d80acdccc7a4e3d30b3acf9a0838a1a9604f4b/public_new3/name-that-llm-lv683-a15.ipynb) documents its 0.684 V13 and uses 40% native embedding, a separate 27B classifier, and a different combination of grouping, complementary inference and balancing. The score is for the complete pipeline. The snapshot is a related notebook, not byte-equivalent evidence for Alex V25.

The [lbjyang V3 export](https://github.com/SSanjay0614/Name-That-LLM-Kaggle/blob/55d80acdccc7a4e3d30b3acf9a0838a1a9604f4b/public_new3/ntl-684-ozertuu-mirror.ipynb) instead adds a Tencent WeMM expert, so the two mirrors are not interchangeable. The mirror operator's [engineering log](https://github.com/SSanjay0614/Name-That-LLM-Kaggle/blob/55d80acdccc7a4e3d30b3acf9a0838a1a9604f4b/action_plan.md#2026-11-12---run-the-0684-pipeline-we-never-ran) reports that a different, nominally verbatim 0.683 recipe scored 0.677 in their account. Attachment drift also occurred in our S07 preparation. Both make exact versions, actual mounted files and runtime branch coverage necessary.

The two mirrored snapshots were checked without executing their code: all 18 Heliosli and 43 lbjyang Python code cells parsed, including the written Python modules. This is a syntax and source comparison, with no inference result. The exact V25 source and the complete version pin ledger remain separate admission gates.

The [native CPU audit](../../scripts/stage14_native_input_audit.py) checks the tokenizer metadata, model index, class manifest, five calibration files and 524 adapter/head tensors per fold, including tensor shape, dtype, byte spans and finite values. It reports SHA-256 fingerprints for the mounted task files. It does not inspect the separate base weight shards, prove tokenizer runtime parity, or verify training exclusions. The [offline notebook builder](../../scripts/build_stage14_native_audit_notebook.py) requires the numeric `datasetVersion` source ID for the public hub; the displayed version ordinal is not sufficient. The check passed on an exact-dimension synthetic fixture and rejected an incorrect pin, nonfinite weights, invalid calibration and a changed tokenizer terminal. It has not run against the real mounted hub. The connected browser became unavailable after verification of the scored notebook and its preview logs, before the hub version and source export could be confirmed.

## Execution gates

1. Freeze the exact source and identify the files it actually reads. Pin each consumed attachment's explicit version, public availability and license; verify the mounted file identity and resolve any broad first-match searches. Verify the Llama input against the approved source and applicable terms.
2. Check the native Qwen base, five adapter checkpoints and calibration data on CPU. Only a run against the real pinned mounts clears that check.
3. Run the native branch in isolation on a fixed set of length-stratified official training passages, with Internet off and free T4 ×2. Verify all five folds complete, both GPUs are used as intended, row and class ordering, finite output, and measured time and memory. A format-only three-row preview is insufficient.
4. Before using a competition submission, demonstrate full offline branch coverage and runtime headroom under Kaggle's nine-hour rule, with exact output IDs, classes and parquet readback. Preserve S07. Separately, any claim of an individual component gain needs same-fold predictions with whole-prompt training exclusions, and paired evaluation before tuning.
