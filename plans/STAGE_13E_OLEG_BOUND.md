# Stage 13E: Oleg corpus upper-bound audit

Run one private, offline CPU audit of [Oleg Zholobov's Name That LLM Response Corpus](https://www.kaggle.com/datasets/olegzholobov/name-that-llm-response-corpus), pinned to Kaggle Version 1. No model fitting or scoring, competition test access, submission, or final selection change. The admission target remains at least **30 previously unused prompt groups**, each with one traceable, competition-like response from all 18 canonical models.

The [Stage 07 inventory](../results/stage_07/REPORT.md) and [source follow-up](../results/stage_07/SOURCE_REVIEW.md) already measured this snapshot. Before relying on that evidence, verify the actual mounted bytes against the earlier SHA-256 fingerprints. Reconcile the short wide table with cell and provenance metadata. Count complete prompt groups by their verified exact prompt group IDs, not the displayed wide row position. Repeat the previously fixed opening-refusal screen and measure the remaining support of each model, plus the total complete groups after the screen. No new filter may be chosen from observed scores.

This is an intentionally generous upper bound: identical user prompts alone do not prove identical full request context; model identity, terms and previous exposure can only shrink the pool. A limit below 30 stops the audit without attaching the competition or doing more expensive overlap work. If the upper bound is 30 or more, report only that further admission checks are required. A changed source, missing file or schema mismatch is an input-verification failure and cannot be reported as zero eligible groups. Export only checksums, counts and the status.

If the pinned corpus cannot clear the threshold, close this external route. The next experiment should isolate a single change to S07 and compare it on the same development prompts with the reused-data limitation stated explicitly. No experimental component score is comparable to the **65.1%** verified official public score of S07.
